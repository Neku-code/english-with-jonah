## Delay diagnosis from source

| Former critical path | Change |
| --- | --- |
| Next waited for `flush()`, then a position request | Window index changes locally first; a coalescing checkpoint queue saves afterward |
| Every dirty answer caused another HTTP request | Bounded answer batches are validated/saved together in one transaction |
| Check required a save request followed by a check request | Check accepts response/revision and atomically saves, grades and completes |
| Vocabulary review caused review + start + full invalidation/navigation | Starting can record review in the same transaction and return bootstrap data; player opens locally |
| Home used seven sequential reads | Two independent database requests |
| Attempt reads locked the student and rebuilt catalogs | Two read queries, no student write lock, explicit ownership/publication checks |
| Lesson opening loaded all attempts and scanned check history for sidebar counts | Latest-version attempt query with LIMIT 1; catalog provides actual question counts |
| Same content/answer save caused redundant revisions | Identical acknowledged values return their existing revision |

These remove identifiable network waits and repeated work. Hosting distance,
cold starts and real-device latency were not measured in this code-only check;
no claim of a measured millisecond improvement is made.

## Code review before commit

Reviewed the modified lesson player, queue, answer/check/submission services,
read DTOs, publication, migration, teacher actions, balance arithmetic and tests.

- Grading keys never enter student DTOs. Final-exam practice checks stay blocked.
- Completion uses every current answer revision, requires all practice marks,
  retains a failed practice attempt for correction and cannot pay twice.
- An old check receipt cannot overwrite correctness for a newer answer revision;
  this review finding has a regression test.
- Batch validation is atomic: a stale answer prevents any partial batch update.
- Checkpoint writes retain the latest position, serialize revisions and preserve
  failed snapshots for retry; UI navigation does not await that queue.
- Teacher coin actions use the protected teacher session and student lock;
  students and cross-origin requests cannot adjust points. Receipts are immutable.
- Existing published content/attempts are preserved. Old student attempt links
  redirect to the latest lesson; original work remains available to the teacher.
- No fourth recurrence of an unresolved defect was reached. Fixes were checked
  through types, service-level regression cases and independent source review.
